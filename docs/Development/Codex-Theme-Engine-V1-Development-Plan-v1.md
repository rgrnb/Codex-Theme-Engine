## 1. 版本修正与文档基线

### 1.1 本次修正

V1.0 的核心交付是：**用户自由导入本地图片和动态视频，将其显示为 Codex 全窗口背景，并获得循环播放、基础性能优化和背景启停能力。**

项目借鉴 Wallpaper Engine 的动态背景体验。图片与视频均为 V1 的必备能力；视频能力不能延后到 V2，也不能以仅支持静态图片的版本替代 V1.0 验收。

| 维度 | v1.1 开发基线 |
| --- | --- |
| 第一阶段定位 | 验证并交付 Background Engine |
| 视频支持 | V1 必须交付 MP4、WebM 的已验证编码组合 |
| 开发优先级 | 接入与渲染可行性、媒体导入、播放稳定性、性能、恢复能力 |
| 后续扩展 | V2 扩展主题系统；V3 再发展分享与在线生态 |
| V1 发布依据 | 本文功能与测试验收全部通过，包含真实 Codex 窗口中的视频背景演示 |

### 1.2 与 PRD、Architecture 的一致性

本次编写依据为当前明确的需求及引用会话中确认的版本修正。**PRD v1.0 和 Architecture v1.0 的完整正文未随任务提供，因此本文不声称已完成逐条核对。** 本文将一致性要求转化为可检查的范围、模块职责和发布条件。

三份文档采用同一版本路线：

```text
V1：Background Engine
    本地图片／视频导入、全窗口背景、循环播放、启停、性能与恢复
                         ↓
V2：Theme System
    在稳定背景能力上增加标准主题包与主题配置
                         ↓
V3：Theme Ecosystem
    分享、创意工坊或在线主题市场
```

取得原文后，按以下项目核对并在同一次文档更新中修正冲突：

| 文档 | 核对内容 | 本文基线 |
| --- | --- | --- |
| PRD | V1 核心场景、必备格式、全窗口定义、启停行为 | 图片与视频同属 V1；见第 2、3 节 |
| Architecture | 接入方式、媒体模块、控制模块、生命周期与数据流 | 先实验定方案，再落实第 4 节职责 |
| Research | 架构证据、方案比较、编码与性能实验 | 服务于阶段 1、2 的技术决策 |
| 旧开发计划 | 是否仍将视频安排在 V2，是否提前开发主题生态 | 以本文件替换当前有效开发入口 |

若旧文档把视频放在 V2，应同步更正为 V1。若架构文档预设的方案无法通过真实视频背景实验，应更新 Architecture 并记录决策，不能通过降低产品目标消除冲突。

### 1.3 执行假设与证据边界

- 本计划暂按 Windows 桌面环境、一个明确选定的 Codex 主窗口建立首版验证基线；具体系统、Codex 版本、处理器、GPU、驱动与显示配置在任务 T01、T02 中登记。若原 PRD 规定其他平台或同时覆盖多个主窗口，应在范围冻结前补充对应任务与测试。
- Electron、React、WebView 或原生客户端均属于待验证候选，不能从项目名称或界面外观推断已采用某种技术。
- 接入能力、媒体解码能力和 GPU 加速状态必须分别验证。第三方运行时文档只能说明该运行时的能力，不能证明 Codex 提供相同接入接口。
- 本文的性能数字为计划验收目标，尚无实测结果；应在阶段 2 出口前固定参考环境与测量方法。

## 2. V1.0 产品目标与功能范围

### 2.1 核心用户场景

1. 用户打开 Codex 和 Background Engine。
2. 用户选择本地图片或视频文件，导入引擎。
3. 用户启用背景；图片静态显示，视频静音自动循环。
4. 背景随目标 Codex 窗口的位置与尺寸变化，用户继续输入、滚动、切换会话和使用工具面板。
5. 用户可切换资源或停止背景；停止后恢复原界面，释放播放与渲染资源。

这里的“上传动态背景”落实为**选择本地视频并导入引擎**。V1 的资源处理在本机完成，云端上传与分发属于后续范围。

### 2.2 V1 必备功能

| 需求 ID | 功能 | V1 交付要求 |
| --- | --- | --- |
| R1 | 图片背景导入 | 支持 PNG、JPG/JPEG、静态 WebP；检查真实文件内容并处理解码失败 |
| R2 | 视频背景导入 | 支持 MP4 与 WebM；至少验证 MP4/H.264、WebM/VP8；发布说明列明具体编码边界 |
| R3 | 全窗口覆盖 Codex | 背景覆盖应用内容区域，处于 UI 后方；位置、尺寸、缩放与窗口状态保持同步 |
| R4 | 动态循环播放 | 视频自动开始、静音、重复播放；循环无引擎引入的黑屏与明显卡顿 |
| R5 | 基础性能优化 | 避免无效渲染和重复播放器；验证硬件解码／合成路径，控制 CPU、GPU、内存与不可见状态消耗 |
| R6 | 背景启停控制 | 提供导入、应用／启用、停止／禁用、切换资源；状态明确，失败可恢复 |

“等格式”表示可在核心能力完成后增加经测试的格式；新增格式不影响 PNG、JPEG、WebP、MP4、WebM 的必备地位。

**格式边界：**MP4、WebM 是容器，实际可播放性还取决于编码与运行时。因此，扩展名筛选后仍需媒体探测和真实解码；不能承诺所有 `.mp4` 文件均可播放。[媒体容器与编码说明（MDN）](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers)

### 2.3 “全窗口背景”的验收定义

- 背景作为一张连续画面覆盖主窗口内的顶栏、侧边栏、会话区域、输入区域和普通工具面板背景，而不是只作用于聊天区域。
- 采用等比铺满策略；允许为适配不同宽高比裁切画面，不拉伸内容。V1 默认使用 `cover` 语义。
- 顶层文字、图标、按钮、编辑器内容、菜单和弹窗保持可读、可操作。背景层不抢焦点，不拦截输入，不降低文字本身的不透明度。
- 对高亮或复杂素材使用统一遮罩或背景明度处理，保障正文和输入内容可读。
- 自绘标题栏纳入覆盖；若客户端使用无法处理的原生标题栏，必须在方案验证报告中登记该范围缺口，不能静默标记为全窗口通过。系统外部边框与窗口阴影不属于背景区域。
- 最小化、关闭或与目标窗口解绑时，背景隐藏或暂停；恢复时重新同步。其他应用位于 Codex 前方时，背景不得独立置顶遮挡它们。

仅在桌面后方播放壁纸、在独立播放器中播放视频，或在 Codex 前方叠加一层视频，都不能替代本项验收。

### 2.4 V1 暂不实现

| 排除项 | 边界与后续安排 |
| --- | --- |
| X1：标准主题包 | V1 不定义 `.codextheme`、主题打包导入／导出、主题依赖或分发格式；V2 再设计 |
| X2：创意工坊 | V1 不开发作者发布、订阅、评分、更新与社区管理；后续生态阶段评估 |
| X3：在线主题市场 | V1 不开发账号、商城、支付、云端资源库与在线下载流程 |
| X4：Wallpaper Engine 完整兼容 | V1 不承诺其场景、脚本、交互、工程文件或 Workshop 订阅兼容；可导入的普通媒体按 R1、R2 检查 |

V1 也不安排主题编辑器、全套 UI 换肤、视频转码器或跨平台全面适配。本地少量配置用于记录背景资源、启停状态和基础显示参数。

## 3. 核心行为与验收约定

| 场景 | 预期行为 |
| --- | --- |
| 首次运行，无资源 | 背景关闭；可导入资源；Codex 正常显示 |
| 成功导入 | 文件复制到引擎管理目录，完成校验并记录资源信息；用户可应用 |
| 取消选择／导入失败 | 保留此前有效背景与状态；给出可理解的结果提示 |
| 启用图片 | 加载并铺满目标窗口；显示图片已启用状态 |
| 启用视频 | 首帧就绪后显示，静音自动循环；显示播放状态 |
| 切换资源 | 新资源准备成功后替换；旧资源释放；失败时保留此前有效背景 |
| 用户停止 | 背景隐藏，视频解码与持续渲染停止，恢复原界面；保存资源选择供下次启用 |
| 窗口最小化 | 视频暂停，停止持续出帧；恢复时在用户仍启用的前提下继续 |
| Codex 关闭 | 解除绑定并释放背景资源；不留下孤立窗口或后台播放器 |
| 引擎重启 | 恢复已选资源及用户启停意图；仅对已验证兼容的客户端执行恢复；错误时保持关闭 |
| 资源缺失／客户端不兼容 | 明确提示，保持或恢复原界面；允许重新导入或重新验证 |

资源复制采用临时文件加成功提交的方式，失败时清理临时副本。V1 可仅保留当前有效资源及一次切换所需临时资源，避免为背景导入提前建设大型资源库。

区分“用户启用意图”与“当前运行状态”。窗口最小化导致的自动暂停不会覆盖用户意图；用户主动停止后，窗口恢复不能自动重新播放。

## 4. 工程结构与方案决策

### 4.1 最小模块职责

| 模块 | 职责 |
| --- | --- |
| Client Adapter | 检测 Codex 版本、发现目标窗口、同步窗口状态、实施经验证的接入与恢复操作 |
| Asset Importer | 选择本地文件、检查内容、探测尺寸／编码、管理副本、返回导入结果 |
| Background Renderer | 图片／视频背景显示、等比铺满、可读性遮罩与合成 |
| Playback Controller | 播放、循环、停止、自动暂停、错误处理与资源释放 |
| Control UI | 导入、应用、停止、切换资源及状态提示；阶段 2 决定采用轻量窗口还是托盘控制 |
| Local Settings | 保存资源信息、启停意图、基础显示参数与兼容性记录 |
| Diagnostics | 记录版本、媒体加载失败、解码状态、帧数据与性能指标 |

上述职责可合并到少量进程或目录，不要求每个模块独立成服务。接入实现与媒体实现保持边界，使后续客户端适配不必重写播放核心。

```text
Control UI → Asset Importer → Playback Controller → Background Renderer
                      ↘ Local Settings                 ↑
                                  Client Adapter：窗口绑定与状态同步
                     Diagnostics：错误、媒体质量、资源与性能记录
```

### 4.2 背景渲染方案验证原则

| 候选方案 | 需要验证的内容 | 主要否决条件 |
| --- | --- | --- |
| 客户端内容层接入 | 是否存在可用接口；能否插入媒体层、调整背景表面并恢复；视频与解码能否正常工作 | 接入不可重复、无法完整恢复、更新后不能识别兼容性，或只能改局部背景 |
| 外部背景／Overlay 窗口 | Codex 表面是否允许显示后方内容；层级、裁切、输入穿透、DPI 和生命周期能否同步 | 目标表面仍不透明、媒体遮挡 UI、背景脱离目标窗口或干扰输入 |
| 客户端资源适配 | 是否可进行版本受控的局部修改；能否备份、验证与撤销 | 无可靠恢复、修改范围不可控，或需要持续手工处理才能运行 |

**工程推论：**外部背景窗口能否成为 Codex 背景，取决于目标表面与合成关系；创建一个透明窗口本身不能证明全窗口背景可行。应把该问题作为实验条件逐项检查。若选择 Electron 作为试验运行时，还需核对其透明窗口、缩放／调整尺寸和输入行为限制。[Electron 窗口样式与限制](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)

阶段 2 必须给出可复现的主方案与否决证据。若所有方案均失败，继续接入研究并更新架构风险；不得转入主题包开发，也不得将静态壁纸 Demo 当作 V1.0 Release。

## 5. 开发阶段与任务拆解

所有任务都应关联需求 ID，保留可复现的验收证据。出口条件未通过时，可并行整理资料或测试素材，但不得宣告进入正式发布。

### 阶段 1：Codex 客户端架构检测

**阶段目标：**确定当前客户端和系统的真实能力，建立后续实验基线。

#### T01：客户端架构与版本调查

- **目标：**回答当前 Codex 客户端由什么运行时承载、哪些信息已经验证、哪些接入点仍未知。
- **实现内容：**登记系统与客户端版本、安装形态、进程关系、可见资源结构、渲染／媒体运行时及可能接口；将每条判断分类为已验证、推测或待实验，记录证据与复现步骤。
- **验收标准：**形成架构检测报告；关键判断均附证据；没有证据时保留未知状态；不把 Electron／React／WebView 预先写成定论。

#### T02：主窗口识别与同步边界

- **目标：**可靠找到背景应跟随的 Codex 主窗口，并明确全窗口覆盖范围。
- **实现内容：**识别主窗口与弹窗；读取内容区域、位置、尺寸、DPI、可见性与最小化状态；调查顶栏、侧栏和面板表面；确定存在多个主窗口时的目标选择行为。
- **验收标准：**连续开关目标窗口 10 次无误绑定；移动、缩放、最大化、最小化与恢复状态可追踪；形成覆盖区域清单和多窗口处理说明。

#### T03：媒体运行时与参考环境探测

- **目标：**确认图片与视频在候选渲染运行时中的可用性，为硬件加速和性能测试建立基线。
- **实现内容：**准备 PNG、JPEG、静态 WebP、MP4/H.264、WebM/VP8 测试文件；探测解码、自动播放、静音、循环与本地资源访问；记录 GPU、驱动及硬件／软件解码路径。
- **验收标准：**完成“环境 × 格式／编码 × 结果”矩阵；MP4 和 WebM 分别有真实解码结果；播放成功与硬件加速验证分别记录；不支持的组合有明确原因或后续调查任务。

**交付物：**架构检测报告、窗口覆盖清单、初步媒体矩阵、参考设备记录。  
**出口 G1：**客户端基线与未知项已登记，可开始背景方案实验。

### 阶段 2：背景渲染方案验证

**阶段目标：**在真实 Codex 窗口中验证图片和动态视频均可作为背景。

#### T04：候选方案最小实验

- **目标：**用实际画面、操作结果和恢复结果筛选接入方案。
- **实现内容：**对可用候选搭建最小实验，加载一张图片和至少一段视频；验证画面在 UI 后方、范围完整、输入正常；检查透明度、层级、DPI 和停止后的恢复；记录失败方式。
- **验收标准：**每个实际可测试的候选都有实验记录；未测试的候选说明缺少的条件；成功方案必须展示真实 Codex 背景，不能只展示独立播放器或透明窗口。

#### T05：全窗口动态背景可行性演示

- **目标：**把 V1 核心可行性提前验证，避免只证明图片方案后才发现视频无法接入。
- **实现内容：**在主方案中依次展示 PNG、JPEG、WebP、MP4/H.264、WebM/VP8；执行输入、滚动、面板打开、窗口移动／缩放、最大化、最小化与恢复；检查全部覆盖区域。
- **验收标准：**五类基线资源可在真实 Codex 中显示；两类视频各循环至少 10 次；UI 可读、可操作；停止后原界面恢复；未解决的覆盖缺口不得标记通过。

#### T06：架构决策与实现约定冻结

- **目标：**将可行实验转成可执行的 V1 工程方案。
- **实现内容：**记录方案选择、证据、版本边界和恢复步骤；定义模块接口、资源副本策略、运行状态、控制入口、显示参数；固定参考设备、必备编码和第 7 节性能目标；列出 PRD／Architecture 的同步修改项。
- **验收标准：**产生一份架构决策记录；图片和视频使用同一背景接入主线；客户端兼容范围、指标及接口可供后续开发和测试使用；没有把标准主题包作为前置依赖。

**交付物：**方案比较报告、全窗口图片／视频 Demo、架构决策记录、冻结后的测试基线。  
**出口 G2：**图片、MP4、WebM 在真实 Codex 中通过核心可行性演示；否则继续研究。

### 阶段 3：图片背景 Prototype

**阶段目标：**完成可由用户操作的图片导入、显示与启停闭环。

#### T07：统一导入入口与图片资源管理

- **目标：**用户能可靠导入自己的 PNG、JPEG、WebP 图片。
- **实现内容：**实现文件选择、内容检查、尺寸与解码校验、受控资源复制和导入结果；处理取消、损坏、伪扩展名、中文／空格路径、只读来源与磁盘不足；预留视频探测入口。
- **验收标准：**三类图片均能导入；修改扩展名不会绕过校验；失败不覆盖当前背景且不留下半成品；完成导入后删除原始文件仍可显示管理目录中的副本。

#### T08：全窗口图片显示与可读性

- **目标：**让图片在所有目标背景表面连续显示，保持 Codex 可用。
- **实现内容：**实现等比铺满、窗口同步和基础遮罩；处理高亮、深色、透明和不同宽高比的图片；对需透明处理的 UI 背景面实施局部适配并保存恢复信息。
- **验收标准：**按第 2.3 节逐区域截图核验；移动／缩放／DPI 切换后无持续缝隙或错位；文字、按钮与弹窗正常；停止后不存在残留透明样式或背景窗口。

#### T09：启停控制与本地配置

- **目标：**用户能看懂当前状态并反复启停、切换背景。
- **实现内容：**提供导入、应用、停止与切换操作；记录有效资源和启停意图；处理目标窗口未打开、配置损坏与资源丢失；启动时进行兼容性检查后恢复配置。
- **验收标准：**完成 50 次启停与切换，无重复背景实例；重启后行为符合第 3 节；用户停止后保持关闭；错误提示包含恢复动作且 Codex 可继续使用。

**交付物：**图片 Prototype、基础控制入口、导入／启停测试记录。  
**出口 G3：**R1、图片部分 R3 和 R6 闭环通过；本阶段仅为中间成果。

### 阶段 4：视频背景 Prototype

**阶段目标：**将动态视频完整纳入同一个用户导入和控制流程。

#### T10：视频导入与能力校验

- **目标：**支持用户导入 MP4、WebM 并明确实际可播放范围。
- **实现内容：**复用统一导入入口；探测容器、视频编码、尺寸、时长、帧率与实际解码结果；区分不支持编码、损坏文件、无视频轨和超出资源策略；默认静音，失败保留原背景。
- **验收标准：**MP4/H.264 与 WebM/VP8 基线样本均通过；不支持编码和伪扩展名样本均有可理解的失败结果；界面不因媒体探测长期阻塞；发布矩阵能够注明经过测试的组合。

#### T11：全窗口视频播放

- **目标：**在真实 Codex UI 后方显示动态画面，并与图片共用覆盖逻辑。
- **实现内容：**创建单一受控播放器，首帧就绪后显示；启用静音和自动循环；复用铺满、遮罩与窗口同步；接入真实解码／合成路径并采集基本播放状态。
- **验收标准：**两类基线视频在前台分别连续播放 10 分钟；各覆盖区域均显示动态画面；操作 Codex 不受干扰；音频不外放；硬件加速可用性有诊断证据，软件回退有记录。

#### T12：图片／视频切换与播放状态管理

- **目标：**各种切换和并发操作不会产生失控播放器或错误状态。
- **实现内容：**实现加载、图片显示、视频播放、自动暂停、停止和错误状态；序列化应用请求或取消过期请求；新资源准备成功后再替换；停止时释放解码器、对象 URL、监听器、定时器和纹理等资源。
- **验收标准：**交替切换图片／视频 50 次并快速重复操作 20 次，无旧请求覆盖新选择；始终只有一个目标背景实例；停止后隐藏背景且不再解码；失败后状态与实际画面一致。

**交付物：**视频 Prototype、媒体能力矩阵、状态与切换验证记录。  
**出口 G4：**R2、R3、R4、R6 的基础视频流程通过；不以独立视频 Demo 代替产品闭环。

### 阶段 5：循环播放与生命周期优化

**阶段目标：**使视频在长时间运行、循环和窗口状态变化中稳定工作。

#### T13：循环接缝与播放连续性

- **目标：**消除引擎引入的黑帧、闪烁和明显回跳停顿。
- **实现内容：**优先验证播放器原生循环；测量末尾到首帧间隔和掉帧；仅在数据证明有必要时增加预加载或双缓冲，并计入内存与 GPU 预算；保留循环时的可用画面。
- **验收标准：**无缝测试素材至少循环 100 次，无新增黑帧；循环间隔达到第 7 节目标；任意素材自身首尾内容不连续不计作引擎故障，但不能以素材问题解释实测播放停顿。

#### T14：窗口状态与基础节能

- **目标：**减少不可见状态的持续消耗，并确保恢复后正常播放。
- **实现内容：**最小化／关闭／解绑时暂停或释放；恢复时按用户启用意图恢复；处理休眠唤醒、显示器变化与目标窗口重建；采用事件驱动同步，保留低频校验，避免高频忙轮询。
- **验收标准：**最小化／恢复 30 次、关闭／重开 10 次、休眠／唤醒 5 次，无黑屏、孤立窗口或重复播放器；主动停止后不自动启用；不可见状态消耗达到第 7 节目标。

#### T15：播放故障与兼容性恢复

- **目标：**媒体和接入失败时，用户能继续正常使用 Codex。
- **实现内容：**处理加载超时、资源不可读、播放错误、渲染进程失效与客户端更新；避免无限重试；接入前保存必要恢复信息；提供一键停止及异常退出后的恢复路径。
- **验收标准：**故障注入后，背景在限定时间内停止或退回有效状态；版本不匹配时停止自动接入并提示重新验证；重启恢复操作可重复；如果所选方案修改了客户端资源，备份校验与撤销演练必须通过。

**交付物：**循环质量记录、窗口生命周期报告、恢复演练结果。  
**出口 G5：**长循环、自动暂停、启停与故障恢复均通过。

### 阶段 6：性能测试与优化

**阶段目标：**用可复现数据证明背景播放不会明显拖慢 Codex。

#### T16：统一性能采集与基线

- **目标：**获得可比较的 CPU、GPU、内存、帧质量和交互数据。
- **实现内容：**按第 7 节采集关闭背景、图片背景、视频背景的数据；把 Codex 与引擎相关进程全部纳入统计；记录系统、版本、驱动、素材、窗口尺寸和设备；为 UI 交互定义可重复脚本。
- **验收标准：**原始数据、样本信息和计算方法可复现；报告包括平均值、P95、峰值和对照差值；掉帧数据与界面可见卡顿分别记录，不用单一 FPS 证明体验合格。

#### T17：性能瓶颈修复与资源预算

- **目标：**使必备媒体在参考环境中达到冻结后的性能目标。
- **实现内容：**依据数据修复重复解码、无效复制、过大纹理、高频同步或不必要重绘；硬件加速不可用时按实际能力降级或提示超出性能范围；4K／60fps 等高负载资源单独评估。
- **验收标准：**PNG、JPEG、WebP、MP4/H.264、WebM/VP8 基线全部达到第 7 节要求；每项优化有前后对照；性能不合格时保留问题并继续修复，不在测试结束后放宽门槛以标记通过。

#### T18：长时间稳定性与完整回归

- **目标：**发现累积泄漏、生命周期问题和优化造成的功能回退。
- **实现内容：**按测试矩阵执行连续运行、循环、资源切换、启停、窗口变化与错误恢复；运行最终资源管理检查；核对用户操作与实际运行状态一致。
- **验收标准：**完成至少 2 小时视频运行和 100 次资源／启停操作，无崩溃与持续资源增长；R1—R6 全部通过；所有阻断项关闭且原始证据已归档。

**交付物：**性能对照报告、稳定性报告、完整测试矩阵。  
**出口 G6：**功能、质量与性能目标全部达标，具备 Release Candidate 条件。

**交付物：**V1.0 安装包或运行包、使用说明、Release Notes、最终测试报告、演示和产品标签。

### 7.3 性能测量方法与计划目标

**以下数值是初始工程目标，不是已验证性能。** 阶段 2 应固定参考环境与素材，并将目标写入测试基线。若需调整，须在正式性能测试前记录理由与变更；测试失败本身不能作为事后放宽标准的依据。

测量流程：

1. 固定机器、窗口尺寸、显示配置、Codex 会话与交互脚本；排除下载和其他高负载任务。
2. 对背景关闭、静态图片、MP4/H.264、WebM/VP8 分别预热 2 分钟，再采样 10 分钟；各执行 3 轮。
3. 保持同样的输入、滚动和面板切换操作，并单独记录最小化和停止状态。
4. CPU 使用全机归一化的相关进程合计占用；GPU 按适配器、解码／合成引擎分别记录，避免相加产生误导；内存使用相关进程的 RSS／工作集总量。
5. 对客户端内部接入方案，背景增量体现在 Codex 进程；对独立方案同时计入引擎和新增辅助进程。所有方案统一与背景关闭对照。

| 指标 | 初始目标 | 口径 |
| --- | --- | --- |
| 图片首次显示 | P95 ≤ 2 秒 | 基线图片，应用操作到目标窗口显示；导入复制耗时单独记录 |
| 视频首次显示 | P95 ≤ 3 秒 | 基线视频，应用操作到可见首帧；至少测 20 次冷／热加载并标注 |
| 停止响应 | ≤ 1 秒隐藏背景；≤ 5 秒停止解码与持续渲染 | 保留少量运行时缓存允许，但不能仍播放或出帧 |
| 基线视频掉帧 | 10 分钟测量期间掉帧率 ≤ 1% | 掉帧数／总帧数；排除加载预热，另列循环与窗口操作事件 |
| 循环间隔 | P95 ≤ 67ms；最大值 ≤ 100ms | 30fps 无缝素材，末尾显示帧到首帧的实测间隔，至少 100 次 |
| 视频 CPU 增量 | 10 分钟平均 ≤ 5 个百分点 | 相关进程合计，相对背景关闭，全机归一化 |
| 视频 GPU 增量 | 解码与合成引擎各平均增量 ≤ 15 个百分点 | 在同一参考 GPU 上分别测量；同时报告 P95 与峰值 |
| 稳态内存增量 | 基线视频 ≤ 400MiB | 相关进程总量相对关闭背景；单独报告峰值 |
| 长时间内存稳定性 | 预热后每个 60 分钟区间净增长 ≤ 50MiB，且无持续增长趋势 | 2 小时运行，结合 100 次切换／启停后的回收情况 |
| Codex 交互影响 | 本地输入／滚动／面板切换 P95 增幅 ≤ 10%，且无重复出现的 >100ms 停顿 | 采用相同可重复操作；不使用模型网络响应时间 |
| 最小化／停止空闲 | 5 秒内暂停解码和持续出帧；CPU 平均增量 ≤ 1 个百分点 | 稳定后采样 60 秒；GPU 解码活动回到关闭背景基线附近 |

若 Web 运行时提供 `getVideoPlaybackQuality()`，可采集总帧数和掉帧数；如不可用，采用播放器或平台等效统计。该计数应与屏幕观察和帧时间数据共同使用，不能代替全窗口合成质量验证。[视频播放质量统计（MDN）](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/getVideoPlaybackQuality)

### 7.4 测试报告与缺陷处理

每条用例记录：测试版本与环境、样本、步骤、预期、实际、通过／失败、截图／视频或性能日志、缺陷链接。

以下问题阻断发布：必备格式不能使用、覆盖范围未达成、遮挡 UI 或拦截输入、循环黑屏／明显卡顿、停止或恢复失败、持续资源泄漏、基线性能不达标、未知版本自动接入造成不可恢复修改。

额外编码或高负载样本的限制可列入已知问题，但必须说明具体范围，且不能破坏必备格式、默认体验或可恢复性。

- 从仓库规定的开发基线创建 `feat/v1-background-engine`；单人小型仓库也可按现有流程在同一功能分支依次提交。

## 9. 主要风险与处理任务

| 风险 | 对 V1 的影响 | 处理方式与任务 |
| --- | --- | --- |
| 客户端架构或接口不符合预期 | 无法实施预设接入 | T01、T04 用证据筛选方案；必要时更新 Architecture |
| 外部背景被不透明表面遮住 | 背景无法在 Codex 中可见 | T04、T05 先验证合成关系，失败即否决该路线 |
| 只覆盖会话区或漏掉顶栏／面板 | 未达到全窗口需求 | T02 建立区域清单；T08、T11、TC07 逐项核验 |
| 透明处理影响文字或操作 | Codex 可读性与输入受损 | 局部处理背景面、统一遮罩；T08、TC09 验证 |
| 容器支持但编码不支持 | 视频导入失败 | T03、T10 真实探测，保证两类必备组合；公开编码边界 |
| 循环停顿或重复解码 | 动态体验与资源预算不达标 | T13、T16、T17 先测量后优化，额外缓冲纳入预算 |
| 最小化仍持续播放、切换泄漏 | 长时间 CPU／GPU／内存消耗 | T12、T14、T18 管理状态、暂停与释放 |
| 客户端更新造成接入失效 | 背景无法使用或原界面受损 | T15、T19 版本匹配、停用、备份与恢复验证 |
| 文档再次把视频移到后续版本 | 开发路线偏离 MVP | T06、T20、T21 核对 R2 与发布条件 |
